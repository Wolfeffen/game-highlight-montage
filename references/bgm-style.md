# BGM 风格手册（FPS 游戏混剪）

> 结论来自实测：同一支莫伊拉 45s 混剪，画面时间线完全不变，只换 BGM，跑 `bgm_onset.py` + `bgm_section_check.py` 对比得出。

## 一、首选风格：强鼓点 + 失真吉他 solo

FPS 混剪（守望先锋 POTG / 瓦 / CSGO / 三角洲）的 BGM 首选 **强鼓点摇滚 + 失真电吉他 solo**，BPM 150-200。
纯合成器电子（无吉他）在密集切点处容易"糊"——短板合成音色缺乏明确音头，切点落上去没有"咬合感"。

### 实测对比（同一时间线，仅换 BGM）

| 指标 | A：纯电子鼓点版 | B：强鼓点 + 吉他 solo 版 |
|---|---|---|
| 检出重音数 | 111 | **128** |
| 中位音头间隔 | 0.32s | **0.30s** |
| 切点↔最近音头 **中位偏差** | 0.085s | **0.060s ← 更跟手** |
| ≤0.15s 对齐率 | **83%（25/30）** | 77%（23/30） |
| 黄金分割点偏差 | **+0.059s（正中）** | -0.221s（偏软） |
| P3 极限快切段平均能量 | — | 0.112（**全片最低**） |
| P4 完整表现段平均能量 | — | 0.153（**全片最高**） |
| P5 收尾峰值 / 鼓点密度 | — | 0.259（全片最高峰）/ 0.6/s（长音） |

### 机制解释（重要）

**吉他 solo 为什么更跟手？**
吉他 solo 是**连续密集的音符流**（音头间隔稳定在 0.30s 左右，比纯鼓点版更密）。切点无论落在哪一帧，附近总能找到一个明确音头 → 中位偏差从 0.085s 降到 0.060s，观感上"每一刀都踩在音上"。

**代价是什么？**
密集音符流里**缺少孤立的重击**，低频冲击力被稀释 → 全片最强的一击不突出。实测 P3 极限快切段（黄金分割点所在）平均能量 0.112，反而比全片平均低 12%，峰值 0.153 是全片最低。**收拳点软了。**

**为什么对齐率反而降了？**
不是音乐变差，是**节奏型冲突**：P3 碎片时长是递减的（0.45→0.35→0.25→0.2s），而音乐节拍是均分的（0.30s 网格）。起点对齐后，后续碎片必然逐格漂移。实测 27.45/27.85/28.20/28.90 四个切点偏差依次为 +0.19/+0.19/-0.16/-0.26，正是典型漂移。

## 二、三条硬规则

1. **吉他 solo 压 P4，不压 P3。**
   P4「完整表现」是完整叙事段（多杀链、绕后击杀链），需要旋律支撑 → solo 放这里（实测能量 0.153 全片最高，正确）。
   P3「极限快切」要的是**鼓组滚奏 / 密集军鼓 / 双踩**，不是旋律 solo。solo 的连绵音头会把碎片的"脆"抹平。

2. **递减碎片必须配 accelerando，或改成节拍整数分。**
   若 P3 碎片时长递减（0.45→0.2s），音乐必须在这一段做加速/滚奏；否则只有第一个切点能对上。
   退而求其次：碎片时长取节拍间隔的整数分（如 0.30 / 0.15 / 0.15），让它落在网格上。

3. **黄金分割点必须是能量峰，不只是"有个鼓点"。**
   判定标准不是"附近有没有重音"，而是 **±1.5s 窗口的平均能量 ≥ 全片平均**。否则就是"收拳软"——画面收了，音乐没收。

## 三、验收清单（BGM 到位后逐项打勾）

用 `scripts/bgm_onset.py` 与 `scripts/bgm_section_check.py` 跑完，对照：

- [ ] 中位偏差 ≤ 0.08s（跟手感）
- [ ] ≤0.15s 对齐率 ≥ 75%（极限快切区密集时 70% 也可接受，因碎片密度可能超过音头密度）
- [ ] 黄金分割点最近音头偏差 ≤ 0.15s
- [ ] 黄金分割点 ±1.5s 能量 ≥ 全片平均能量
- [ ] P4 段平均能量 ≥ 全片平均 ×1.15（高潮型）或 P3 段最高（收拳型）——**二选一，但不能都不满足**
- [ ] P5 收尾有独立长音/重击峰值，鼓点密度自然下降（给 LOGO 留空间）

## 四、收拳软 / 切点空档怎么救：外科手术式补强

音乐整体不错、只是收拳点不给力时，**不必重新生成**。直接在原曲上叠合成打击音，
画面一个不动，连重渲染都省了（视频流 `-c:v copy` 直拷）。

实测（守望先锋 46.7s 成片，同一条 ACE 曲子）：

| 版本 | 对齐率 | 中位偏差 | 黄金点能量比 | 黄金点偏差 | 总分 |
|---|---|---|---|---|---|
| 原版 | 77% | 0.060s | **0.88** | -0.221s | 74.7 |
| 补强后 | **83%** | **0.050s** | **1.18** | **+0.019s** | **82.3** |

步骤与参数细节见 `references/ace-step.md` 第四节。三个要点：

1. `scripts/make_impacts.py` 生成 `tick.wav`（0.15s 短促打击）与 `impact.wav`（1.5s 大重击）。
2. 偏差 >0.15s 的切点各补一记 tick；**黄金分割点最近的那一个切点补 impact**（全片唯一一记最强重击）。
3. 先 `volume=0.72` 留余量，混完 `volume=1.35` 提回；**限幅只做兜底**——狠限幅会压掉动态，
   实测音头从 128 掉到 112，反而制造新的偏差点。

> 判读提醒：补打击音会抬高频谱通量的标准差，使检测阈值上移，
> 所以对齐率有 2-3 个点的噪声。以**黄金点能量比**和**黄金点偏差**为准。

## 五、给 ACE / Suno 的 Prompt 要点（经验版）

- 必写：`driving rock drums, distorted electric guitar solo, aggressive, BPM 150-200, no vocals`
- P3 段单独强调：`snare rolls / double-kick, accelerando, no sustained melody`
- P4 段单独强调：`full guitar solo, chorus energy, melodic lead`
- 黄金分割点：**显式要求一记孤立重击**（`one isolated massive impact hit`），并说明"前后 1s 内不要有密集音符"，否则冲击被稀释。
- 收尾：`final sustained chord, tail out, leave space for logo`
